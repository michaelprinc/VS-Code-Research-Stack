## Defects found and closed in this phase

Found by measurement or by reading the shipped code, not by design review. Each now has a test or a gate.

| # | Defect | How it was found | What closes it |
|---|---|---|---|
| 1 | **Python outbound capability was reported, never gated.** A second packaged `.py` member reaching the network would have passed the audit silently. | Design review of the gate itself. | `REVIEWED_PYTHON_NETWORK_MEMBERS` plus per-member bounds and transport call-site counts, refusing in both directions. |
| 2 | **The audit found a second outbound member the code scan had missed**: `extension/bundles/theological-research/scripts/crossref_lookup.py` (`urlopen`, Crossref and OpenAlex, `TIMEOUT_SECONDS = 30`). | Running the gate against the built artifact rather than the source tree. | Named in the reviewed set with its own bounds. Lesson: a source-tree scan and a payload scan are different measurements. |
| 3 | **`media/controls.js` read `view.authorized`, a field the state model never sends.** The "Turn off" button never rendered, and "Add API key" was always marked unavailable — in the shipped 0.3.11 panel. | Reading the renderer against the view builder. | Both fixed to `view.authorization === "authorized"`, plus a new test that every `view.<field>` the renderer reads is a field `integrationViews` actually sends. |
| 4 | **A check that answered badly was worded as "not checked yet".** `unknown` fell into the "this release does not understand" branch and produced the same sentence as a profile that had never been checked. | Wiring the new outcome through the panel. | `PROBE_EFFECTS.unknown` and a distinct `WORDING["answered-badly"]` sentence. |
| 5 | **The 6 000-byte guard on `integrations.py` could not hold** for the five-state classification (2 bytes of headroom). | The implementing agent reported it instead of churning reviewed content. | Guard raised to 6 200 with the reason recorded in the test; capability assertions unchanged; growth 122 bytes. |
| 6 | **The byte-ceiling projection was wrong.** A module was assumed to count twice in the artifact; only the `extension/worker/` copy is packaged. | Measuring the built artifact: 1 365 400 of 1 376 256, not 1 381 161. | The ceiling was **not** raised. Headroom is 10 856 bytes and the real accounting is member by member. |
| 7 | **`Retry-After` was designed in as a provider behaviour.** It is undocumented for Semantic Scholar and absent on a real 429. | The documentation review, against the OpenAPI specs. | Backoff with jitter is the mechanism; a carried `Retry-After` is an opportunity. No sentence may promise a wait the provider named. |
| 8 | **Verified automatic installation was assumed feasible.** No official installer checksum exists; Linux has no signature. | Probing the live release directory and the official docs corpus. | DD12-15: guided installation, and the Toolkit says why automatic is not offered. |
| 9 | **The card and the Quick Pick each had their own label table for the same record.** `INTEGRATION_ACTIONS` and `CARD_ACTIONS` could offer two different things from one state, which is the same class of defect as #3 seen from the other side. | Reading the two tables against each other while wiring the new guided actions. | One list computed from the record — `integrationViews()` sends `view.actions` as `[id, label]` pairs and both surfaces render it. A new gate asserts every action id the model can offer has a card entry, so an offer cannot be silently dropped. |
| 10 | **`integrations.py` passed its own byte guard** — 7 302 against `assert len(...) < 6200`, 1 102 over. | The implementing agent reported it instead of quietly trimming reviewed operator-facing text. | Guard raised to 7 400 with the full history and the reason recorded in the test; the capability assertions in the same test are unchanged. The wording that caused the growth (the confirmed Zotero setting sentence, the silent-drop sentence, the three-state detail) was kept. |
| 11 | **The shipped probe addressed Zotero as `localhost`.** Zotero binds IPv4 loopback only, so a host where `localhost` resolves to `::1` would refuse or miss, and the probe would have reported a running Zotero as `not-installed`. | The documentation review's Zotero 10 findings, checked against the constant in the shipped worker. | `ZOTERO_LOCAL_API`, `ZOTERO_CONNECTOR_PING` and `ZOTERO_LOOPBACK_ORIGIN` are all `127.0.0.1`, and all three are now reviewed bound literals in `scripts/verify_vsix.py`, so a revert to `localhost` fails the audit rather than shipping. |
| 12 | **Zotero 10 silently drops a request that does not look like it came from its own client.** A dropped request produces no answer at all, which the probe had no category for and would have collapsed into "not running". | The documentation review, against the shipped request builder. | `Zotero-Allowed-Request: 1` on both endpoints, and a new internal code `ZOTERO_NO_ANSWER` for a request that connected but produced no usable answer, reported as the existing `unknown` outcome with a sentence naming the drop. |
| 13 | **The byte ceiling was breached and the audit was the first thing that said so.** Headroom was known to be 10 856 bytes at the start of the phase; the phase spent 39 455 and nothing measured it until `verify-package` failed. | `npm run verify-package` returning `VSIX audit failed: unpacked payload exceeds the 1376256 byte preview limit (1383104 bytes measured)`. | Ceiling re-measured to **1 441 792** (one 1/16 MiB step) with member-by-member attribution in `scripts/verify_vsix.py:128-152`, and the chain 1 343 649 → 1 365 400 → 1 383 104 recorded. The process lesson is in `.agent/LESSONS.md`: a known headroom is not a budget unless something measures the spend before the gate does. |
| 14 | **The two halves of INT-15 disagreed at their own boundary.** The Python writer capped the facts file at 8 192 bytes while the JavaScript reader capped what it would read at 4 096, so the Toolkit could write a record it would then refuse as oversized. The same shape appeared in the timestamp: the writer accepted `detectedAtMs = 0`, the reader required `> 0`. | Cross-checking the two contracts after both halves landed — not a failing test; every test on each side passed. | Reader raised to 8 192 to match the writer, with the reason recorded in `integrationprobe.js`; both Python sides now refuse a non-positive moment; a new test asserts a zero-dated fact is refused and leaves no file, and a new host test straddles the bound (7 000 accepted, 9 000 refused naming the number). A boundary is a contract and both ends must state the same number. |
| 15 | **The probe told the operator it "writes nothing" after it began writing something.** `READ_ONLY_WARNING` and the detail sentence said nothing was written; the probe now records one machine-level fact outside the workspace. | The implementing agent reported the wording rather than rewording reviewed text on its own. | Both sentences now say **"no workspace file"**, which is what is actually true, and the module docstring names the fact file and states it holds a classification and a timestamp and never a credential. The `integrations.py` guard moved from 7 400 to 7 600 for that accuracy, with the reason recorded in the test rather than the statement trimmed to keep the old number. |

## Deliberately left open

- **INT-13B verified automatic installation** — DD12-15. Not a gap in the work; a decision with a source.
- **Unattended execution of any installer** — DD12-12. The package has no reviewed place in which to do it.
- **Zotero write access, Zotero cloud, cross-profile secret sharing, an alternative metadata provider** — unchanged exclusions.
- **A live Zotero, a real key, a real Windows host, a real Extension Host** — unreachable in this container; no case in [acceptance.md](acceptance.md) claims one.
- **A real browser rendering of the new panel actions** — `extension/test/browser.test.js` cannot run here (see acceptance.md §5 for both routes that were attempted).
