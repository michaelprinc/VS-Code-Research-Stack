# Research Stack Toolkit 0.3.14 quality review and 0.3.16 proposal

19 November 2026 · Engineering review and release proposal

**Verdict.** The local 0.3.14 VSIX matches its build receipt and passed both package checks on Windows. It adds useful corpus retrieval, explicit tool presets and bundle recovery. Windows test portability and live VS Code behavior still need release evidence. For 0.3.16, the smallest useful integration is to let the official Mistral Vibe panel call the Toolkit’s existing local MCP workers through Vibe’s workspace configuration. The release criterion is a real research workflow in that panel with Copilot disabled, followed by a Copilot regression run.

## Proposed 0.3.16 behavior

### Connect Vibe to the verified workspace worker

Target the official extension `mistralai.mistral-vibe-code` in local VS Code Desktop. Vibe ships its own agent and uses the shared Vibe configuration model for MCP. The Toolkit already resolves versioned managed Python and computes which worker modules a preset needs. Reuse that launch logic for the existing VS Code provider and the Vibe preview. Keep the two configuration destinations independent so users can use either or both interfaces with the same research data. Initial acceptance should cover a single trusted workspace folder on Windows. Extend claims to other hosts only as they acquire receipts. [Mistral installation and authentication](https://docs.mistral.ai/vibe/code/vs-code-extension/install-authenticate) · [Extension settings](https://docs.mistral.ai/vibe/code/vs-code-extension/settings) · [MCP configuration](https://docs.mistral.ai/vibe/code/cli/mcp-servers)

Show the chosen folder, preset, worker version, aliases, modules and expected tool names before saving. Make each server a Vibe `[[mcp_servers]]` table with `transport = "stdio"`, the checked absolute interpreter, the worker’s existing flags and environment keys. Generate tables only for modules selected by the preset. The Toolkit filters its own tools before discovery, so Vibe inherits the selected surface without a second manually maintained allow-list. Vibe exposes tools using `{server_name}_{tool_name}`. The same local worker can return document content to a remote model through the client session, so use synthetic documents for the release run. [Toolkit launch definition](../../extension/extension.js#L1225) · [Vibe configuration reference](https://docs.mistral.ai/vibe/code/cli/configuration-reference)

Illustrative 0.3.16 preview for `find-in-notes`, which selects three read tools in the document module. `RESEARCH_STACK_REQUIRE_PRESET` is the proposed opt-in to strict preset handling. The generator should resolve the path for the current workspace and serialize spaces, quotes, backslashes and Unicode.

```toml
[[mcp_servers]]
name = "rsk_documents"
transport = "stdio"
command = "C:/Research/Projekt č/.research-toolkit/managed/worker-0.3.16/.venv/Scripts/python.exe"
args = ["-I", "-B", "-X", "utf8", "-m", "research_stack.mcp_server"]

[mcp_servers.env]
RESEARCH_STACK_WORKSPACE = "C:/Research/Projekt č"
RESEARCH_STACK_TOOL_PRESET = "find-in-notes"
RESEARCH_STACK_REQUIRE_PRESET = "1"
```

### Handle settings, trust and lifecycle

- Use the workspace `.vibe/config.toml`. Validate the effective project/user configuration before enabling a writer. Vibe gives project settings precedence, so check whether adding project MCP entries shadows inherited user servers on the pinned extension version. If compatibility or an ownership collision is unresolved, provide a copyable preview and leave the operator’s configuration untouched. Preserve unrelated tables and entries and avoid copying secrets. Use a TOML-aware merge with validation, a pre-write edit check, a backup and an atomic replacement for edits the Toolkit can safely own. Keep machine-specific paths in local configuration and flag them as non-portable in the preview. [Vibe configuration precedence and trust](https://docs.mistral.ai/vibe/code/cli/configuration)
- Treat the saved preset and worker path as a snapshot. Detect drift after a preset switch, workspace move, upgrade or rollback, and offer a new reviewed preview. Update or remove only entries identified as Toolkit-owned and detect edits since the last save. Cover reload and reconnect in the real panel. Mark the workflow verified after a Toolkit tool call succeeds. [Vibe panel commands](https://docs.mistral.ai/vibe/code/vs-code-extension/commands-slash-commands)
- Let Vibe handle its authentication and tool approvals. Report missing extension, untrusted folder, missing worker, invalid TOML, alias collision, stale configuration and blocked MCP distinctly. Start with a read-only preset for onboarding. Retain the current provider-specific credential paths and document which require separate proof in Vibe, including Zotero write credentials held in VS Code SecretStorage. Add the explicit local Toolkit MCP workflow before promising external GitHub presets, live external providers, multi-root or remote workspace behavior. [Vibe authentication](https://docs.mistral.ai/vibe/code/vs-code-extension/install-authenticate) · [Vibe MCP administration and permissions](https://docs.mistral.ai/vibe/code/cli/mcp-servers)
