## 5. Contradictions P7 found between the documents and the code

1. **Command count.** The P7 brief said `contributes.commands` is "currently 44" and named a "remove archive entry" command. The tree says otherwise: `main` has 39; the working tree has **43**; the fourth command is `researchToolkit.configurePresetTools`; there is **no** remove-archive command anywhere (`extension/bundles.js` exports none, no such command id exists). While P7 was working, `extension/package.json` declared 42 with `configurePresetTools` registered in `extension/extension.js` but not contributed — the inconsistency HR-33 exists to catch — and the release owner landed the missing entry. At the time this note was finished the pins agree: `extension/scripts/check-installed-payload.js:287` asserts 43, `extension/test/unit.test.js:66,80` pin 43 contributed and registered (and 44 disposals with the status bar item), `extension/test/integration-host.test.js:942,947` pin 43. Every P7 document states **43** and names the commands rather than relying on the count.
2. **Retrieval-state names.** The release-notes draft listed `current` and `unsupported-schema` as states. `records.py` returns `ready`, and the unreadable-store case is a refusal receipt, not a state. Corrected in the draft, the changelog and both READMEs.
3. **The 0.3.13 "9 + 91 = 100" bullet** misnames the preset and quotes three estimates that the vendor inventory contradicts (45 default-toolset names, 27 read-only). Annotated in place.
4. **`README.md` claimed 0.3.12 added `researchStack.integrationTimeoutMs`.** It did not; the packaged `extension/worker/README.md` carries the same sentence because `scripts/build_worker_bundle.py` copies this README byte-for-byte. P7 corrected the source; **the worker copy and `dist/` must be regenerated by the packaging package**, which owns `extension/worker/**`.
5. **`README.md` claimed the store's backup and recovery were not provided**, while `store_maintenance` backup / staged restore / vacuum has shipped since 0.3.5 and is exercised in `tests/`. Annotated rather than deleted.
6. **Phase 4 records state a ≤12-tool preset budget** that `extension/presets.json` no longer declares. Annotated in both phase-4 files.
7. **The research map recommended 20 toolkit verbs for `research-max-github-full`** (112 total, which breaks the 20-tool headroom). The shipped preset carries **16** verbs, giving 108 and exactly 20 headroom — the shipped file is what the docs state.
8. **`extension/guides/toolkit.md` said "Install the 0.3.12 VSIX"** (finding R15-05). Guides are outside P7's file set; the guide in the tree now names the 0.3.14 VSIX and `worker-0.3.14/installation.json`, so no P7 edit was needed there.
9. `extension/README.md` was carried in the working tree with CRLF endings against `.gitattributes` (`* text=auto eol=lf`); P7 normalised it to LF. Content change is limited to the corrections above.
10. **The packaged changelog names one release.** `MARKETPLACE-CHANGELOG.md` held a 0.3.13 section; with P7's 0.3.14 section it carried two `## x.y.z —` headings and `check:installed-payload` fails `2 !== 1`. The marketplace page is the curated notes for the current release, so the 0.3.13 section was replaced by the pointer line and a "carried forward" bullet (see §1). `extension/CHANGELOG.md` keeps both entries, with its own `/^## \d+\.\d+\.\d+ —/` headings free to repeat because it is not a package member.
11. The preset counts P7 states agree with the guides the maintainer already brought to 0.3.14 (`extension/guides/onboarding.md` 16 + 92, 20 + 42, "everything in the table except the two presets named below"); no guide was edited by P7.
