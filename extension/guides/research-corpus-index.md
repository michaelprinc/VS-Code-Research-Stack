# Workspace corpus index

Index the Markdown, text, PDF and DOCX sources you select so searches return the same chunk identities every time.

## Setup

The **Corpus index and record store** component step (offered by the Full package) creates `.research-toolkit/store/research.sqlite3` in the selected workspace. The managed worker then serves `index_corpus`, `unindex_corpus`, `search_corpus` and `verify_sources` through the "Research Toolkit Corpus index & record store" MCP server, which the extension supplies automatically once setup has run. No third-party database, vector store or embedding model is installed. Text-bearing PDF is read with pypdf page by page and DOCX with python-docx item by item; a PDF whose text lives only in scanned images is reported as a source with no text units, never guessed at.

Selecting the Full package alone installs nothing; the step runs only when you start it. These verbs reach the assistant through the **Index, search and record claims** preset, which carries all ten store verbs, or through the **Full research workflow** preset (the Full default), which carries `index_corpus` and `search_corpus`; both state that the corpus index and record store step must be completed, and a preset the package does not offer falls back to the package default.

## First task and readiness

Call `index_corpus` with `paths: ["notes/your-notes.md"]` and `mode: "index"`. The result reports the run id and status, the sources indexed, the chunk count, an index fingerprint, and any source that produced no chunks (`emptySources`), failed (`failedSources`) or was read only partly (`partialSources`) — an emptied file stops being searchable instead of keeping its old text in the index. A partial or failed read never replaces what is already indexed: its previous version is kept and named in `keptPreviousVersion`, and the incomplete version is stored only when you pass `accept_partial: true`. Then call `search_corpus` with `query: "your topic"` and a small limit; each hit carries `source_path`, `locator`, `chunk_id`, `content_id`, `text_sha256` and the source hash, and `read_text_source` reopens that passage with adjacent paragraphs. A Markdown or text hit is located as `paragraph=N;chars=a-b`, a PDF hit as `page=N;chars=a-b`, a DOCX hit as `paragraph=N;chars=a-b` or `item=N;kind=table-1-row;chars=a-b`, so a quotation points at a page or an item of the original document rather than at a line of extracted text. `store_status` reports each source's parser, chunker, coverage (units read, units with text, empty units, failed units, batches), warnings and outcome — `complete`, `partial` or `failed` — alongside the freshness state recorded by the last `verify_sources` call. Identical content at two paths indexes as two traceable occurrences. `unindex_corpus` drops selected sources from the current index while keeping any chunk a stored claim still cites. Ready means the reading check indexed a synthetic fixture, searched the stored chunks, verified the indexed sources against the files on disk and recorded a fingerprint.

## Troubleshooting and limits

`STORE_MISSING` means the store step has not run in this workspace. `SOURCE_COUNT` and `STORE_CHUNK_LIMIT` bound one call to 1000 files and the store to 20000 chunks; split large corpora across calls. `UNSUPPORTED_FORMAT` means the file is not Markdown, text, PDF or DOCX. `SOURCE_CHANGED_DURING_INDEX` means the file changed while it was being read — the run keeps the previous version and indexes the file again. `SOURCE_TEXT_TOO_LARGE` means the extracted text passed 5 000 000 characters, and a PDF or DOCX larger than 25 MiB is refused before it is opened. A source whose units could not be read carries `UNITS_UNREADABLE`, `NO_TEXT_UNITS` or `NO_TEXT_EXTRACTED` and an outcome of `partial` or `failed`; that is a report about the file, not a silent empty index. A score is relevance ranking, not a truth claim. Re-indexing replaces the rows for the selected paths only, in one transaction, so a partial run cannot silently drop the rest of the index. Source files are read only and never modified — `verify_sources` re-reads them and writes only to the store. Vector and hybrid retrieval, embeddings, reranking, cross-workspace indexes and any recognition of text in scanned images remain planned.
