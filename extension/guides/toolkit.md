# Research Stack Toolkit

Manage package preferences, inspect components and find onboarding guides.

## Setup

Install the 0.3.8 VSIX through Extensions: Install from VSIX. Reload when requested. Open the beaker sidebar or Research Toolkit: Open Control Panel. Choose a local workspace, open **Component setup for this package** and run **Set up package components** — setup checks workspace trust, the host tools the plan needs, the managed paths and the setup lock before it writes or downloads anything — then read the **Installation status** card and run Run MCP reading check or Read selected PDF / DOCX. If a step was recorded but the files it produced are gone, **Update or repair component steps** re-runs it; **Refresh component status** re-verifies the produced files without running the MCP check; **Retry Failed Component Steps** re-runs the steps whose last attempt failed or was blocked. The version comes from the running extension manifest, not the selected package. Save a package preference and a tools preset; the preset selects the goal-shaped tool surface your assistant is offered. The plan the panel runs is declared in `components.json`, each completed step is recorded in `.research-toolkit/managed/worker-0.3.8/installation.json`, and every attempt is recorded in `.research-toolkit/logs/`.

## First task and readiness

Save your package preference, select a research folder and run Check component status, then Check components. The **Installation status** card names the outcome of the last component setup — `Installation complete — N component step(s) verified.`, `Installation incomplete — N step(s) verified, M need attention (step ids).`, `Installation failed — <step>: <error>.`, `Setup blocked — <reason>.`, `Setup cancelled — N step(s) already completed were kept.` or `No component setup has run in this workspace yet` — with a row per step (status, duration, attempts, exit code and error), the host tools setup resolved, and the action that clears the failing or blocked step. It is read from `.research-toolkit/logs/last-setup.json`, so a reopened panel or a reloaded window shows the same verdict. **Open Setup Log** opens the newest attempt log; **Copy Installation Diagnostics** copies the verdict, host tools, preflight results, per-step attempts and the log file path to the clipboard. The setup section names each step this package offers as installed, outdated, needing repair or deliberately omitted; **Update or repair component steps** re-runs the steps an earlier toolkit release recorded plus any recorded step whose produced files are missing, and **Refresh component status** re-verifies those files without running the MCP reading check. Each component row offers Install or Update where the toolkit can install it. **Diagnose tool limit** and **Copy preset summary** report the same budget from the Command Palette. Read Installation and Readiness separately. Guide opens local setup steps; Latest docs opens the maintained official source. Under Tools preset, choose the goal you are working on and open its context estimate: tool count, headroom under the 128-tool client ceiling, and the estimated size of the tool definitions. **Research Toolkit: Select Tools Preset** offers the same choice in the Command Palette.

## Troubleshooting and limits

Ready confirms this controller is running, not that every component is usable. If controls are missing, check the active VS Code profile and extension enablement. Package choices and tool presets do not install tools; a preset only changes which tools the managed workers register. Setup runs only when you start it, resumes after a cancelled or failed run, and never overwrites existing files. A step that needs another step pulls its prerequisite in and says why; when a step fails, the steps that do not depend on it continue and its dependents are reported as blocked with the step that blocked them. If uv is not found, setup is blocked before anything is written and the message names the locations searched — point `researchStack.uvPath` at the executable and reload the window. A downloading step that needs longer than the default 900 seconds is reported as timed out; `researchStack.setupTimeoutSeconds` (60–3600) raises it. **Clear Interrupted Setup Lock** removes only a lock classified as stale — older than the setup window, or older than 60 seconds with a dead owner process — and refuses a live one. A preset saved for a package that does not offer it falls back to that package's default. External tool counts in the estimate are published vendor figures, not measurements made here.
