# Changelog

## 0.3.15 — Public Preview

**0.3.15 measures what 0.3.14 shipped, and fixes what the measuring exposed.** The store's three retrieval modes were benchmarked, the retrieval figures are published with the limits of the measurement stated beside them, the store now refuses a read it cannot honestly answer instead of ranking part of your index, every search hit names the ranker that found it, the Zotero write path answers the way Zotero's own local API answers, and the theological-research bundle ships at catalog version 2.2 with text that describes the Toolkit as it now is. The panel, the presets, the commands and the tool surface are the ones 0.3.14 published: **43** commands, eleven store verbs, ten offered presets, and the three max presets with their named GitHub selections are unchanged.

- **Retrieval, measured — on a synthetic corpus.** 29 judged queries (10 Czech, 10 English, 5 diacritic-free-or-typo, 4 with no relevant answer) over 40 chunks of text authored for the measurement, five repetitions, deterministic. Over the 25 assessed queries: **Recall@10 0.940** in all three modes; **nDCG@10 0.882** lexical, **0.842** vector, **0.887** hybrid. Latency, median (p95): **1.09 ms** (1.44) lexical, **2.68 ms** (3.58) vector, **3.33 ms** (4.38) hybrid. At the store's 20 000-chunk ceiling a full scan costs a median of 253.69 ms lexically and about 1.57 s with the vector or hybrid ranker. All four queries with nothing to answer still returned a hit in every mode, because no relevance threshold is applied — a weak score stays visible rather than the result reading as an empty library. **One query (`ty-01`) returned Recall@10 0.000 in every mode; that is reported as an open ranking defect, not a fixed one.** These figures compare the three modes on text written for the purpose: they are **not** a measurement of your library, your library was not available to this build, and the vector backend `rsk-hashing-v1` is a **lexical signature, not a semantic model** — no synonym, no negation, no translation, no model download.
- **A store over its ceiling is reported, not half-searched.** A store already holding more current chunks than the reviewed 20 000-chunk limit is now refused **before any chunk is loaded** — by `search_corpus` in all three modes, by `embed_corpus` and by the status reads — with `STORE_OVER_LIMIT_READ`, naming the counts it found, why scoring a slice of your index would be a silent misreport, and the steps that clear it. Beside it, `foundBy` on every hit (`lexicalOnly`, `vectorOnly` or `both`) says which ranker produced that result, and the search summary counts the three groups. A store over the limit still answers `store_status`, `verify_sources`, `evidence_read`, `claims_read` and `claims_write`; retired rows never count towards the limit.
- **The Zotero write path does what the local API actually requires.** A JSON **array** body belongs to a POST and one object to a PUT or PATCH, because an object where an array belongs answers 400 `Uploaded data must be a JSON array` — which is what 0.3.13 sent, and why a write the Toolkit reported had never been accepted. The keys a write created are read out of the answer's `success` map and anything in `failed` is reported instead of swallowed. A filing is verified by **re-reading `GET /collections/<key>/items`** and comparing it with the snapshot taken before the write: a 200 or 204 on the request is not evidence that anything arrived, and a filing that answered 204 into a collection it never reached is now caught. `export` can be scoped to one collection while stating that no export format carries membership. Zotero's own special collection names (`My Publications`, `Unfiled Items`, `Duplicate Items`, `Retracted Items`, `New Items`, `Feed Documents`) are refused **before any request is made** — the local API cannot see a special collection, so a Toolkit-made one would be an imitation. What the Toolkit still refuses by name is unchanged: no delete, no merge, no duplicate checking, and `undo` needs a journal that actually holds the write it is replaying. The eight operations it offers are named in code (`ZOTERO_WRITE_OPS`); **one confirmation authorizes at most 25 operations per batch × 4 batches = 100 operations**, and the preview names that number (`authorizedOperations`, `batchesNeeded`) instead of leaving it implied; `ensure_collection` never re-parents a collection it finds under another parent (`ZOTERO_COLLECTION_PARENT_MISMATCH`, naming the key and both parents); a paged collection listing that did not finish is reported `truncated` and is never used as a census; `collections` is not a writable item field, because a filing is the item update that answers 204; tags cannot be read for one collection (`ZOTERO_COLLECTION_TAGS_UNSUPPORTED` — read them from the library status or from the item); and a collection the write created is recorded `undoable: false` with its reason named.
- **Provider readiness says which situation it is reporting.** The four answers to "why was nothing asked of this provider" are now named separately, so a consent you gave in the panel that the checked process was not handed reads as *recorded but not carried* — with the next step being the Toolkit's own card, not a confirmation you already gave — instead of looking like a missing consent. A provider reservation is now released on every exit path that stores no result, including the one where the request itself errored, so a failed call no longer leaves the next call deferred behind a claim nobody holds. Measured anonymously on 22/23 November 2026: Crossref and OpenAlex answered on every route asked; **Semantic Scholar's field fill could not be measured** — every anonymous request was refused with HTTP 429 in this container, and an anonymous 429 is the provider's global pool, not this Toolkit's allowance. Semantic Scholar stays disabled until you read its licence and activate it yourself.
- **The theological-research bundle is catalog version 2.2, and its text says what the Toolkit does.** Its reference file describes the store as it now is — three retrieval modes, schema 4 with `chunk_vectors`, claim statuses, the `access/` `topic/` `type/` tag vocabulary, and Zotero's own export carrying no access label — and the bundle's own `SKILL.md` no longer contradicts it. Its Zotero reference — the member whose change is why the packaged revision moved — gained the distinction its text was missing: **a tag labels a record, a collection is where a record is filed**, `ensure_collection` never re-parents a collection it finds under another parent (`ZOTERO_COLLECTION_PARENT_MISMATCH`, naming the key and both parents), Zotero's own special names are refused **before any request is made**, `collections` is not a writable item field, and a filing is the item update that answers 204 rather than the `POST /collections/<key>/items` shape. The authors' `metadata.version: "2.0"` in the frontmatter and this Toolkit's packaged **2.2** in the catalog are recorded side by side so neither drifts. An installed 2.0 upgrades to 2.2, a file you edited is archived and kept, and a restore writes the reviewed bytes back through the same hash-verified staging every bundle write uses. Its duplicate-report script now caps its detail at **40 lines** and says it is capped; `--verbose` or `RST_DEDUPE_VERBOSE=1` prints the full report, and the machine-readable summary and exit codes are unchanged.
- **How this release was exercised, and where that stops.** `scripts/verify_mcp.py` now picks the worker launcher for the platform it runs on instead of naming one, so the development reading gate runs on Linux and macOS as well as Windows. Node test fixtures build a junction rather than a symlink where the host needs it, and where a link fixture cannot be built the test is **skipped with the reason recorded** — a skipped test is a gap in this record, not a pass. `npm run test:browser` ran for the first time, with `playwright` pinned as a **development-only** dependency that ships in no artifact: it renders the shipped panel markup in Chromium, and a Chromium window is **not** a VS Code webview — no editor sandbox, no editor theme, no Settings write — so those cases belong to `npm run test:host`, which now names the artifact a run exercised (the source tree, or an installed candidate identified by its digest and member count).
- **Carried forward, unchanged in this release:** the ten offered presets and the three max presets with their GitHub selections (the GitHub figures are the vendor catalog's published tool names, and no GitHub MCP server was started on the build host); **Configure Preset Tools for Copilot** and the workspace `.mcp.json` it writes, with the token left as an environment reference; bundle force-update with archiving, archive history and hash-verified restore; the 0.3.13 Zotero read surface and validated RIS preparation; both topic skill bundles carrying their own MIT licence; the package's `LICENSE.txt`, `SUPPORT.md` and `SECURITY.md`; and from 0.3.10 the optional Marketplace update check (one bounded HTTPS GET, at most once a day, switchable with `researchStack.checkForUpdates`) and the operator-reviewed problem report.

**What this release does not claim.** No 0.3.15 artifact had been packaged, audited, installed or published when this page was written, and this page carries no byte counts, member counts, payload limits or artifact hashes: the packaged payload's figures belong to the repository's release record (`.agent/QUALITY_STATE.md` and the phase-16 acceptance table), because a page inside the archive cannot certify the archive that contains it. **A Toolkit write to a real Zotero 10 library is still unverified** — every Zotero behaviour above is proven against an emulated Zotero 10 answering with the responses measured on the operator's host. The retrieval figures above are not a measurement of your corpus, and `ty-01` is an open defect. The reference-host work is still owed: installation of a 0.3.15 candidate on the reference Windows host with the four panel scenarios in a real Extension Host, whether a junction reads as a link on NTFS, a live GitHub `tools/list` and how a Copilot client honours the file the Toolkit writes. Qdrant, a CPU embedding model, DuckDB, a Playwright browser capability and institutional provider adapters each carry a recorded decision to **defer** them for this release, with the condition that would reopen each. Scanned documents still need OCR outside the Toolkit, notebooks still need a kernel you set up, Zotero still has no delete or merge, and the four release gates G1–G4 remain open. 0.3.15 is a local deliverable: it is not published on the Marketplace.
