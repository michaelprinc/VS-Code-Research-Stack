# Changelog

## 0.3.14 — Public Preview

**The Full package's store now retrieves with two rankers, and it says which one found a passage.** `search_corpus` answers in `lexical` (the stored BM25 path, unchanged), `vector`, or `hybrid`. The vectors are computed by the Toolkit's own CPU backend — `rsk-hashing-v1`, 256 dimensions, word tokens plus character 3- and 4-grams — from the chunk text already in your store: no model download, no network call, no new dependency, no third-party database. A new command verb, `embed_corpus`, builds or rebuilds them. It is a **lexical signature**, not a semantic model: it reaches `iluminacích` from `iluminace`, and it does not know that "pilgrimage" and "journey" are the same idea. Hybrid hits carry the rank, score and backend of both rankers, and a stored vector is used only when it matches the backend, the dimensions and the text it was made from — otherwise it is reported as stale and the Toolkit names the verb to run. The store moves to schema 4 with an additive 3→4 migration that keeps every chunk and every claim link a 0.3.13 store already had; a migrated store has no vectors until you run `embed_corpus`. `lab-state.json` is now rewritten from the store by every store-writing verb and states the retrieval state it measured (`not-built`, `partial`, `stale` or `ready`). `draft` is a claim status.

- **Three max presets, each naming its tools.** `Maximum research: GitHub full plus the whole store` (16 Toolkit tools + 92 named GitHub tools = 108 of the 128-tool client ceiling, exactly 20 tools of headroom), `Maximum research: GitHub as read-only evidence` (20 + 42 read-only named GitHub tools, with the server's read-only switch and an explicit exclusion of all 35 write tools) and `Maximum research: the whole local store, no GitHub` (20 Toolkit tools, no third-party surface). The per-preset Toolkit cap moves from 12 to 20, the Full default preset reaches 15 tools so the journey now runs to `verify_sources` and `claims_export`, and the retired `Documents + third-party evidence` and `Maximum research lab` presets keep working for anyone who saved them while no longer being offered. GitHub figures are the vendor catalog's published tool names, counted from that list — no GitHub MCP server was started on the build host.
- **Configure Preset Tools for Copilot** writes the selected preset's exact GitHub tool list into the workspace `.mcp.json` the Copilot harness reads, keeps a copy of what it replaced, refuses to overwrite an entry it did not write, refuses the older `.vscode/mcp.json` shape that has no tool-list field, and never writes a credential: the token stays an environment reference. Read-only in a tool list is a filter, not a permission boundary — your token decides what the account may do.
- **A topic skill bundle you edited is not lost.** `Force Update Topic Skill Bundle (Archive First)` lists every file it would replace and what state each is in, and copies the bytes it replaces into `.research-toolkit/bundles/archive/<bundleId>/<stamp>-<sequence>/` before writing anything, with an index and a plain-text log naming the absolute path of every archived version. `Show Bundle Archive History` lists them; `Restore Bundle Archive Version` verifies the archived bytes, archives what it replaces and then writes them back. An archive is never rewritten and never deleted.
- **Two settings for the readiness checks.** `researchStack.integrationTimeoutMs` (default 80 000 ms, allowed 40 000–300 000) and `researchStack.integrationCooldownSeconds` (default 10 s, allowed 5–300 s) replace values that were fixed inside the extension. A value outside the range is clamped and the clamp is stated. They bound the Toolkit's own check and its re-check window; they do not make a service answer sooner and they do not raise the worker's own per-request limits.
- **A rollback states what its check proves**, naming the checker release and the runtime release and what their pairing does and does not establish.
- **Carried forward, unchanged in this release:** the 0.3.13 Zotero surface (`zotero_library` for reads, `zotero_write` with a preview that sends nothing, a snapshot before the first change, a journal `undo` can replay, version guards, and no delete, merge or duplicate checking) with its validated RIS preparation; the structural validation of generated RIS and the `TY - GEN` fix; both topic skill bundles carrying their own MIT licence; the package's `LICENSE.txt`, `SUPPORT.md` and `SECURITY.md`; and from 0.3.10 the optional Marketplace update check (one bounded HTTPS GET, at most once a day, switchable with `researchStack.checkForUpdates`) and the operator-reviewed problem report that redacts personal facts before anything is sent.

**What this release does not claim.** The retrieval above is a lexical-signature ranker inside the store: no embedding model is downloaded and no vector service is installed, so Qdrant, DuckDB, a CPU embedding model, Playwright and institutional adapters stay `kind: "planned"`. Scanned documents still need OCR outside the Toolkit, notebooks still need a kernel you set up, Zotero still has no delete or merge, and a Toolkit write to a real Zotero library is still unverified. Vector and hybrid retrieval have local tests but no benchmarked relevance study and no retrieval-quality figures. Reference-host installation, Extension Host and rendered-window receipts remain outstanding, G1–G4 remain open, and the GitHub tool counts above still need a `tools/list` from a real host. 0.3.14 is a local deliverable: it is not published on the Marketplace.
