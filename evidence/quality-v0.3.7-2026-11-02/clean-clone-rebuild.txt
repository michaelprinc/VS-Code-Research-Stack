## Why the tag moved between the runs, and why that is not a gap

`e0192ad` carried the release; `eeb2f08` adds only this receipt and two records about it —
`git show --stat --name-only eeb2f08` lists `.agent/QUALITY_STATE.md`,
`evidence/quality-v0.3.7-2026-11-02/README.md` and this file, and no packaged path. Runs 3 and 4
rebuild from the later tag instead of relying on that argument. The same holds for any later commit
that touches no packaged path; re-run the command above to confirm it for a given tag.

## What makes two trees build the same bytes

- `.gitattributes` (`* text=auto eol=lf`) keeps the committed blobs LF, so the clone's text is the
  tree's text; `extension/scripts/package.js` normalises the staged tree to LF anyway and
  `scripts/verify_vsix.py` refuses CRLF in any packaged text member.
- `package.js` sets `SOURCE_DATE_EPOCH=315532800`, which vsce honours by stamping every ZIP entry with
  that date and sorting members by path; the verifier refuses any other timestamp.
- `package.js` gives every staged file mode 0644, which the ZIP records in `external_attr`; the
  verifier refuses any other mode outside the three members vsce writes itself
  (`[Content_Types].xml`, `extension.vsixmanifest`, `extension/readme.md`).

Before those three fixes existed, two clone builds seconds apart produced three different digests with
byte-identical members.
